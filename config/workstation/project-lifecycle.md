# Project Lifecycle

## Placement

- Start disposable exploration under `~/Projects/_scratch/YYYY-MM-topic`.
- Promote durable implementation to `~/Projects/<area>/<project>` once it has
  a clear purpose, owner, or continuing value.
- Keep the canonical Git repository in the durable project root; use branches
  and worktrees rather than copied project directories for parallel work.

## Agent workflow

1. Classify the request as idea, prototype, active development, maintenance,
   testing, release, or archive.
2. Create new agent-owned material in the matching location.
3. Before moving existing durable content, show a plan, inspect references and
   Git state, choose a recovery path, and obtain approval.
4. Add concise project guidance when a project gains durable conventions that
   future agents need to know.

## Graduation signals

- A scratch project graduates when it needs a stable name, Git history,
  dependent work, or a release path.
- A durable project archives only after its references, remotes, recovery path,
  and active ownership are understood.
